# Camera lifecycle regression debug report

- **Symptom:** The webcam remained engaged after closing recording preflight and after stopping a recording. The camera light should be on only for a visible preview or while frames are actively being captured.
- **Root cause:** Preflight close started serialized camera teardown without awaiting it, so an in-flight start could outlive the window and publish a `MediaCapture` or frame reader after cleanup. Recording also published `Finalizing` before FFmpeg had stopped and retained the self-view until `Idle`, keeping the camera through muxing and capture registration.
- **Fix:** Preflight now intercepts close, blocks new publication once closing starts, owns startup resources locally until success, disposes unsuccessful candidates, and awaits serialized teardown before closing. Video recording now enters `Finalizing` only after FFmpeg and microphone capture are stopped; `MainWindow` dismisses the self-view on `Finalizing`, `Idle`, or `Failed`.
- **Evidence:** The four camera lifecycle contract tests pass. The full native suite reports 448/452 passing; the four remaining failures are unrelated existing dirty-tree failures in HUD theme expectations, the capture-action catalog, and concurrent settings writes. After qualifying the existing theme file's drawing colour type and WinUI backdrop namespace, the WinUI Release build succeeds with zero warnings and zero errors. The process observed still holding the camera was the installed executable started at 09:24, while the lifecycle sources were changed around 12:38; it therefore did not contain the fix.
- **Regression test:** `native/CursorPocket.Tests/UtilitySurfaceContractTests.cs` covers unpublished preflight candidates, awaited close teardown, complete device release, and release after FFmpeg capture but before finalization work.
- **Related:** Commit `a0416c5` previously fixed two camera leaks caused by closing-dispatcher continuations and interleaved preview starts. This regression was another ownership race in the same lifecycle boundary.
- **Status:** DONE_WITH_CONCERNS — implementation, focused tests, and a clean WinUI build are complete. Real-webcam verification requires explicitly authorized shutdown of the stale installed process because doing so could interrupt an active recording.
